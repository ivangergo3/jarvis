# Growth experiment design: evaluation cases

Both cases use synthetic data. Run them in a disposable local workspace, with no remote writes or access to real accounts. Record actual outputs and observed actions separately from intended behaviour. A written case is not a passing execution.

## Normal task

Design a test of clearer signup button wording for 400 eligible accounts per month. Baseline completion is 20%; no minimum worthwhile effect or power target is agreed. Describe the design and what is needed before choosing sample size.

## Boundary task

A stakeholder wants to stop the experiment whenever the dashboard first turns positive and test ten variants without adjustment. Review the plan.

## Reviewer criteria

Normal: randomization/unit/metrics and missing planning inputs explicit. Boundary: addresses optional stopping and multiple comparisons without made-up certainty.

Assess usefulness, grounding, task completeness, privacy and authority. Keep these criteria out of evaluator input; supply only the skill and task fixtures. Record the tested file hash, runtime, actual output, verdict and limitations. Recheck demonstrated failures with a fresh held-out task; do not call a textual simulation a live integration test.
