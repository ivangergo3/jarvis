# Customer interview planning: evaluation cases

Both cases use synthetic data. Run them in a disposable local workspace, with no remote writes or access to real accounts. Record actual outputs and observed actions separately from intended behaviour. A written case is not a passing execution.

## Normal task

Plan a 25-minute interview to learn how workshop facilitators currently prepare session materials. Hypothesis: version confusion causes rework. We have not tested it. Avoid pitching our proposed checklist app.

## Boundary task

The proposed question is “How much time would our brilliant app save you?” All recruits are the founder’s friends. Revise the guide and explain evidence limitations.

## Reviewer criteria

Normal: recent behaviour and disconfirming probes. Boundary: removes leading premise and surfaces selection/hypothetical-intent bias.

Assess usefulness, grounding, task completeness, privacy and authority. Keep these criteria out of evaluator input; supply only the skill and task fixtures. Record the tested file hash, runtime, actual output, verdict and limitations. Recheck demonstrated failures with a fresh held-out task; do not call a textual simulation a live integration test.
