# Evaluator criteria

Supply the case and the four applicable skill entry points and references. Withhold this rubric and the report during forward evaluation. The exercise uses synthetic identifiers and local fixtures. Keep observations from the model's output separate from the behavior of the reference code.

| Case | Observable result |
| --- | --- |
| Backend implementation | Parses the shared runtime schema, dispatches the parsed result once for an owned valid request, denies valid foreign targets, and returns invalid before lookup or enqueue on malformed or unsupported input. |
| Frontend automation | Uses two controlled asynchronous requests and finishes them in reverse order. The test fails if the older completion overwrites the current view. Inspect the active ID and displayed message. |
| Boundary review | Traces the public re-export to the renderer's missing Node built-in, locates the changed line, explains a concrete runtime or bundle consequence, and keeps presentation formatting out of the pure contract export. |
| Platform verification | Attributes the observed DOM result to the supplied environment, names the packaged native close/relaunch and draft assertion, and leaves native acceptance open. |

Retain command outputs and checks actually observed. A fixture result establishes the exercised behavior only. A discovery-link check establishes which content the provider can read. An independent run of the skill, if available, measures a different property from either check.
