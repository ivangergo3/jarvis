# Local wire contracts

The browser and backend import stable typed IDs and wire values from `@jarvis/contracts`. A request names its entire destination by ID, including its worker generation and request revision. IDs use a canonical lowercase UUID. General command IDs are random version 4 UUIDs. Timestamps use UTC with three fractional digits. Decimal cursors fit a signed 64-bit counter, with zero as the initial cursor. Revisions and event sequences start at one.

The pinned Zod 4.6.7 declarations reference the WHATWG URL type. The pnpm patch gives Zod’s URL helpers a module-local type when the consumer compiles with only ES2023 libraries. Consumers with native URL declarations retain that type. The patch changes only TypeScript declarations.

The public lifecycle schemas distinguish the observed provider outcome from cleanup of its local worker. A verified local exit alone leaves the provider effect unknown. An interrupted outcome requires a verified provider interruption. Record worker cleanup independently for any state when there is evidence about the run’s registered helper. A terminal-unsent input can retain its setup fence and record a verified worker exit together. Omit the field when there is no observation, except for interrupted runs where cleanup must be explicit. Unavailable requests carry one safe reason. Private prompts, channel handles and answers belong to the authorized request flow. Unknown state values require a compatible consumer.

## Snapshot pages

Create a reader with `createSnapshotReader(ownerId, snapshotId)`, using the authenticated owner and a fresh snapshot UUID. Pass the original JSON text of each page so it can enforce the 1 MiB UTF-8 limit, including escapes and whitespace. Each page holds up to 100 public records. Repeated JSON keys are rejected, including different escaped spellings of the same key.

The first page has `pageToken: null` and offset zero. A later page echoes the previous `next` as its token. The owner, snapshot ID, total record count and high-water mark stay fixed. Producers sort rows by the ASCII key returned by `snapshotRecordKey`. The reader validates ordering within and across pages while retaining only the prior key. A final page has `next: null`. A zero high-water mark describes an empty snapshot.

Apply data only after an `ok` response. A malformed page or an unsupported version cannot advance the reader. Discard an expired or mismatched partial projection, then start a fresh snapshot. Public records contain safe request status. The service’s authorized live route supplies any private prompt. [Local command and event contract](../../docs/engineering/local-command-stream.md)

## Event replay

Pass an original JSON event to `decodeEvent`. For a batch, pass the original text plus the authenticated `ownerId`, last applied `after` cursor and a required `hasApplied(eventId)` lookup to `readEventBatch`. The lookup uses that owner’s committed projection history. After an accepted batch, commit the projected changes, event IDs and new cursor together. A repeated ID at a new sequence is invalid, including after a restart. Compare decimal cursors numerically with `BigInt`.

The wire reader limits each event envelope to 64 KiB before decoding the batch. JSON separator whitespace counts towards the batch limit. Formatting and escapes inside an envelope count towards both limits. A batch holds at most 100 events and 1 MiB of original UTF-8 data. Known event kinds must carry their original project, session, run and request ancestry. Unknown kinds still require a stable target, owner and contiguous sequence. An incompatible version or event kind produces a compatibility status only after those common checks pass. Gaps, repeated IDs or keys, wrong destinations and malformed data stop the replay without advancing it.

An `ok` result contains the validated events. Every other result omits them. For a trusted locally constructed object the `Event` and `EventBatch` schemas are available. Actual projection, authorization and durable cursor storage belong to the consuming service.

## Task commands

A general mutation uses one random UUIDv4, the originating Jarvis Auth session, and its controller admission epoch. Compare a parsed revision-bound run command with trusted state using `matchesRunRevision` immediately before applying it. Use the immutable project/session/run/request IDs in the command and an expected revision for revision-dependent changes. A run submission identifies the frozen repository/provider binding and a sealed draft's revision, ordered image references, content IDs, byte lengths and SHA-256 digests. A command has a required non-null operation, target and version. A submission has a required non-null payload and text reference. Image-only input uses sealed empty text and one to six normalized PNGs. No raw filesystem paths, provider credentials, editable display names or image bytes travel in this command.

A `Receipt` reports a committed local result. A definitive refusal and an unsent retirement are separately recorded ledger states. A transient `ServiceError` or missing receipt cannot settle a command. Run events report independently observed provider outcomes. A Cancel receipt also returns the recorded run revision and observation, including an existing terminal result. Compare receipt IDs, owner, originating session, controller epoch, fingerprint and operation/target against the saved outbox entry. Clear only its acknowledged draft revision. The service must resolve foreign/invalid IDs, deduplicate, enforce quotas and authenticate every operation.

Staging uses a separate monotonically increasing owner sequence and writer epoch. `stagingCommandId` encodes the sequence in a canonical UUIDv8. Bits 0–61 occupy the UUID’s low 62 payload bits and bit 62 occupies the lowest pre-variant payload bit. All other custom bits are zero. Chunk and image requests carry validated binary bodies separately from their metadata. Authenticate, validate normalized PNG dimensions/bytes or assembled UTF-8 and grapheme count, and verify the digest before committing. A cursor lookup returns the current writer epoch independently of its last receipt. Query and recovery handles are opaque and bound to their stated owner, session, immutable content and snapshot or ledger range.

Resolve a `LiveRequestTarget` on the current generation, channel, authorization session and revision before returning private content. Read and verify its entire immutable content before allowing an answer. `matchesPrompt` verifies offered decisions and answers only after the private prompt and answer schemas parse. These helpers grant no permissions. Store only public metadata in events, general history and diagnostics.

Takeover control requests use a separate UUIDv7 namespace, so even a replaced takeover receipt’s ID cannot become an ordinary command or a numbered staging write. Every staging write names its originating Auth session. The service compares it with the authenticated session at commit. A staging retirement also identifies the original, now inactive session. An image receipt carries the attachment ID once in its image reference.

Keep free-text answers in the private, live-request delivery path. The general answer command carries only a private answer ID, byte count and SHA-256 digest. Bind and verify those bytes, the request revision, worker channel and active session before delivery. Private prompts admit up to 1 MiB of encoded JSON, and private answers up to 64 KiB. Both admit at most 128 questions or answers, and each question at most 128 choices. Use the bounded wire parsers and refuse an over-limit prompt in full.

A retirement targets one command ID. Its payload identifies the prior session, admission epoch, operation, original target and fingerprint. Consequently the full original target of a retirement being retired is also a single command ID; its earlier preconditions remain bound by the original fingerprint.

To recover a pending prompt from snapshot metadata, call `request.describe` with its stable request target. Only the original active session can receive the `LiveRequestDescriptor`. Its verified target and content ID identify the private `request.content` stream. Do not persist that descriptor in generic history.

Receipt inventories, pinned draft manifests and history use the same page bounds as snapshots. Bind each response to the requested owner, epoch or session, fixed high-water mark, total, expected record offset and opaque continuation before using it. Verify increasing sequence or revision across page boundaries as well as within each page. Each draft manifest distinguishes open indexed chunks from a sealed text reference. History exposes retained content, removal markers, safe decision categories, outcomes and explicit gaps.

When reading a catalog, ledger, draft or history page, pass the original wire text, authenticated owner ID and validated read request to `parseReadPage`. It checks the 1 MiB limit before parsing JSON and matches the response to the requested scope. The caller keeps the accumulated offset, total and previous row across successive responses.
