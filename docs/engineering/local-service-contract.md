# Phase-one local service and lifecycle

Electron main owns the lifetime of one local Nest service. Nest is the only scheduler and owns its Codex workers. The renderer can select a Jarvis destination, submit input and answer an attributable request through typed operations. It never receives service credentials or process control. The local command API and the measured dependency preflight are specified separately. [Command receipts and event replay](local-command-stream.md) · [Complete lockfile increments](phase-one-dependency-sizing.md) · [Design issue #108](https://github.com/ivangergo3/jarvis/issues/108)

## Start and sign in

1. **Start on open.** Live development and packaged builds for one Mac login share a private installation identity, controller lock, permanent service lock, execution slot and database. A second live controller focuses the owner. The first controller under its lock authenticates a surviving service before it may launch another. A synthetic installation has a separate namespace and a fake provider. No login item or launch-time dispatch.
2. **Bind the service generation.** Under controller then service lock, commit a fresh generation secret to the narrowly entitled shared Keychain group and its generation/key pin to a private launch record. Supply child credentials over an inherited pipe. Nest takes the service lock, verifies the same record and publishes its authenticated birth identity and ready state. It retains that lock through process exit. A superseded or stalled pre-ready launch receives no worker authority and expires under an independent ten-awake-second watchdog.
3. **Authenticate every connection.** Use pinned, mutually authenticated TLS 1.3 over a private Unix socket with HTTP/1.1. Bind the generation, roles and fresh nonces to each TLS session. Disable early data. Use separate connections for commands and SSE. The authenticated controller can obtain bounded health/readiness and shutdown status, and stop its own generation even when storage or user login is unavailable.
4. **Unlock owner data.** Initial setup provisions a single local Supabase Auth user, records the immutable owner UUID and database identity in backend-only settings and disables open registration. The controller signs in or restores through its install-time-pinned local Auth gateway. Validate TLS identity before sending credentials. Disable redirects and proxy fallback. Store the refresh credential in Keychain. Verify issuer, audience, signature, expiry, exact owner and active original Auth session before each product operation. Wrong owner or unavailable verification locks private data. This login is independent of Codex.
5. **Cover the private surface.** Bind every read, buffered event, image and draft to its current owner-session epoch. Use a display lease of at most five seconds and never beyond session expiry. The trusted renderer enforces expiry independently of a stalled controller. On sign-out, revocation, expiry or loss of verification, cover the window, revoke content handles and discard late responses. Qualify the first compositor-visible frame after forced sleep across expiry. If the packaged build cannot keep the private surface covered, leave private display unavailable on that configuration.

## Bind input and provider state

Electron’s native picker supplies a trusted repository selection. Pin the checkout’s filesystem identity, Git common-directory identity and registration revision under the repository lock. Linked worktrees share one fence. Reject independently writable scopes that overlap, including nested checkouts and still-fenced old registrations. Before accepting a send, freeze its local owner, original Auth session, project, conversation, checkout/revision and selected managed Codex user, workspace and backend origin. Require exact matches at lease acquisition, actual dispatch and any recovery lookup. A workspace switch parks a provably unsent run and fences an ambiguous run under its original binding. Sending to a different provider destination requires a separately confirmed new command for proven-unsent input. A moved checkout, changed registration or unavailable confinement requires a fresh verified selection and explicit reconfirmation of the affected draft.

Persist each draft revision and verified private normalized image copy before promising a save. Preserve Swift’s 16,000 extended grapheme clusters, image-only sends, six images and image validation limits. Stage text in at most 64 KiB per indexed chunk. Seal contiguous bytes using total length and SHA-256 before validating UTF-8 and graphemes across chunks. Bind every attachment ID, MIME type, length and digest to the same owner/session/revision. Accept identical retries and reject conflicting bytes. Run creation verifies every reference. Retain pins for current drafts, outbox entries, runs, history and restorable input. A discard releases only its own reference. Before accepting a save, upload or run, account for actual physical copies across the editor, staging and retained history. Enforce a 32 MiB per-owner budget for staging metadata, including indices, manifests, receipts and deduplication tombstones. Reserve before insertion and enforce logical-key uniqueness under the same transaction; exact retries cannot consume another allocation. Exhaustion refuses new staged inputs without touching existing records or reserved stop/outcome capacity. Cap retained input text at 128 MiB and normalized images at 1 GiB per owner across all these states. Reserve the whole accepted write, space for the latest pending draft and mandatory run outcomes, and 2 GiB of free disk for private saves and outcome persistence before optional writes. Cap optional outputs separately under the command contract. Refuse new uploads/runs when either quota or reserve would be crossed. Retain already committed data. The owner may explicitly discard an obsolete draft or remove retained history content, leaving its tombstone. Credit space only after the last pin and private copy are released. Pinned outbox or unresolved-run bytes survive reclamation. Check the pinned provider’s complete frame and scalar limits separately. Refusal retains the input and names the failed constraint. A narrower composer allowance needs owner acceptance under UI-21.

**Protocol target.** Qualify `codex-cli 0.169.0-alpha.11.1` App Server, JSON-RPC over private stdio. Record the verified binary identity and requalify on change. Jarvis launches with a private profile, approved first-party HTTPS origins and an allowlisted environment. Disable alternate credentials and providers, repo overrides, telemetry, diagnostic export, plugins, hooks, MCP and background memories. Use synthetic startup, login, a memory-eligible thread and post-turn idle to verify zero unapproved network, model or tool activity. Unknown methods grant no authority.

## Schedule one attributable run

Across live builds, allow one active turn, one writer per repository identity and 20 queued runs. Budget each worker tree for 32 descendants, a 1 GiB aggregate RSS intervention threshold, ten aggregate CPU minutes and 512 MiB of quota-limited scratch. Account for short-lived and detached children. At a limit or loss of reliable accounting, fence execution and invoke verified cancellation. A platform without qualified containment cannot dispatch live work.

| State | Durable observation |
| --- | --- |
| Queued | Local acceptance receipt and frozen destination. No provider handoff. |
| Preparing a thread | Before any new `thread/start` or resumed setup bytes, commit setup intent, RPC identity and frozen worker/repository/provider binding. Capture whether setup was never sent, handed off or possibly handed off. No user-turn intent or bytes exist yet. Close or crash reconciles setup separately. A possibly created thread stays fenced pending an exact read-only match. The submitted input can be restored as unsent when its missing turn handoff is proven, without automatically creating another thread or releasing the setup fence. |
| Dispatching | Bound worker, repository and provider thread, command ID, run intent and client message ID precede the first provider turn bytes. |
| Running or waiting | Bound acceptance or independent attributable evidence. Each actionable question/approval retains its original channel, request ID and revision. |
| Cancel requested | Cutoff established or explicitly pending. Cooperative acknowledgement alone cannot settle the effect. |
| Terminal | Proven completion, refusal, failure or interruption recorded once. Distinguish provably unsent cancellation, verified forced exit and the provider’s separately observed outcome. |
| Unknown | Ambiguous write, unbound notification or missing proof. Retain the command tombstone and repository fence. Process exit alone cannot prove a provider outcome. |

Reserve an unarmed generation/role/epoch before starting an inert helper. It has no profile or work authority. Before credentialed launch, register its verified supervisor and direct stop capability with Electron, durably acknowledge it and arm the exact epoch. The supervisor holds the Jarvis profile lock until its entire tree exits. Apply this to sign-in, qualification and history readers too. Electron serializes registration, arming and the launch grant against its generation cutoff independently of database availability. Closing admission atomically closes new registrations and arming, captures every already registered supervisor, and revokes pending rendezvous. A delayed helper cannot arm or launch afterward. Account for each pre-cutoff reservation, including each inert helper’s actual exit, before completing cleanup. A missing reservation inventory or uncertain arm stays fenced through reconciliation.

Authorize each protected frame through a one-use local Auth permit bound to the original session, exact operation, generation and epoch. Order permit commit against revocation. Earlier revocation denies the permit. A committed permit is an authorization observation, separate from provider handoff. Recheck known revocation, expiry, repository and stop state at actual nonblocking write. Lost permit acknowledgement cannot authorize a retry. Order actual process launch and the final possible frame write against the cutoff. Require an independently revocable writer if it can stall with a grant. A possibly completed write remains outstanding. Encode compact JSON with no trailing whitespace and reserve its closing brace and newline for a single nonblocking write within the pipe atomic-write bound. Earlier writes cannot leave a syntactically complete request at EOF. If that final write could have succeeded, classify the frame as outstanding. Retire any partially written stream. Its independent supervisor retains the last write handle until the original provider reader and inheriting readers are verified dead, including during TERM, KILL, takeover and writer revocation. Never append an interrupt to a retired stream. If supervisor loss could close the pipe, the incomplete-prefix rule must still prevent delivery of a valid frame. Qualify last-handle loss and teardown with the actual pinned reader; disable dispatch unless zero retired work frames can execute at EOF.

After a normal verified terminal turn, close stdin for orderly exit and reap the whole tree. After two awake seconds, TERM verified survivors and allow their full five awake seconds before KILL. An existing Cancel or Close retains its established grace schedule. Release the execution slot and profile only after verified cleanup.

## Confirm Close or Command-Q

Both controls show the same native confirmation, including active and queued counts. Cancel preserves work, drafts and the window. Before accepting edits, establish durable private draft storage and an unclean-generation marker. Identify pending saves in the UI. A crash can recover only the latest verified revision. [Owner’s shutdown decision](https://github.com/ivangergo3/jarvis/issues/108#issuecomment-7065937405)

1. On Confirm, freeze edits and sends, close new admission and send one shutdown ID to Nest and directly to every registered supervisor. Save the decision and latest draft revisions concurrently with stopping work. Under the database admission lock close that generation and sweep any already committed queue entry. Its provably unsent input remains restorable at the original destination. Neither a stalled Nest nor a blocked save can postpone direct stop.
2. Establish the actual handoff cutoff for each worker. Attempt cooperative `turn/interrupt` immediately on the bound turn. Give the task **60 awake seconds** from the later of cutoff and its first observed interrupt handoff. If the turn ID arrives before escalation, deliver once and give the full interval. If it stays unavailable or a stop is definitively undeliverable, record why and allow 60 awake seconds from cutoff. Bound nonblocking stop delivery to two awake seconds from the first eligible attempt. An ambiguous final write requires fencing that writer and allowing a full interval from its last possible handoff.
3. After voluntary grace, TERM each verified surviving recipient. Record its boot, birth identity and awake timestamp immediately after successful submission. Wait **five awake seconds per recipient** before KILL of that verified survivor. Newly observed descendants receive their own TERM and full interval. Allow two more seconds for exit evidence. Repeated Cancel, Close and takeover preserve the original observations. A failed/unobserved signal cannot start a shorter deadline. A boot-scoped monotonic awake clock pauses these intervals during sleep.
4. Apply the same discipline to every owned profile role. Cancel the original managed login or stop a qualification/read sequence. Even during an Auth/database outage or after the original user session expires, is revoked or is replaced, confirmed controller shutdown can use each captured original preauthenticated stop-only handle. That handle explicitly authorizes one cooperative `turn/interrupt` for that exact worker, thread and turn, including a verified late turn ID. A sign-in supervisor can likewise cancel only its bound login. These stop frames bypass the ordinary work-permit transaction and follow the same observed handoff/grace schedule. The handle grants no work frame, answer, read or replacement-channel authority. Individual Cancel closes only that run. Close adopts its observed schedule and also stops other owned workers. A new login cannot select a different run, worker or PID to signal. The captured handle follows its original owned supervisor through session changes and expires on verified teardown.
5. Verify worker-tree cleanup and persist observed outcomes including unknown. Stop Nest last. Allow two awake seconds for orderly exit, then use its own verified TERM, five-second interval, KILL and two-second exit observation. Reconcile its authenticated shutdown record and service-generation lifetime lock. A pre-ready child needs launch-specific exit proof. An admitted service's retained ready record and acquisition of its unchanged permanent lifetime lock can establish its exit even when its final record is missing. Verify worker cleanup, draft saves and durable outcomes independently. A free lock, timeout or missing PID alone cannot complete shutdown.
6. Close the window only after verifying the decision, latest text/images and all owned cleanup. If saving, persistence, ownership, timing or exit cannot be verified, keep it open and explain exactly what is unresolved. Preserve local Supabase, unrelated processes and the existing Swift app/data.

## Reconcile crash and sleep

A renderer reconnects to its authenticated live service. Controller loss fences dispatch. A successor reconciles the original launch/stop records, supervisors, outbox, queue and known or uncertain handoffs before admission. A pending decision never proves an affirmative click. Preserve established awake deadlines. Missing timing or ownership evidence requires fresh proof and explicit confirmation before restarting a full grace period.

If Nest died, its worker channel is gone. The original supervisor retains stop/cleanup authority only. After verified tree exit, a successor can retire the original epoch and arm a separately registered recovery-only worker under the same frozen owner/repository/provider bindings. For that read-only operation, authorize each lookup under the requesting owner’s current verified Auth session, even if the original work session expired. Bind its new, expiring permit to the recovery epoch, exact stored run, original provider identity/workspace/origin and allowed read method. Recheck current session before each lookup and drop it on revocation. The fresh session restores no execution or decision grant from its predecessor. Permit only handshake, identity and bounded history lookup. Reap it before release. For an uncertain setup, a qualified exact match can recover only the durable thread binding. Resume work only through new explicit owner authorization after reconciliation. A run with an uncertain effect continues to fence its repository. After proven quiescence, other nonconflicting repositories can run. The owner may acknowledge the original unknown effect and release only that repository by command ID, exact run and expected fence revision. This action neither reclassifies nor resends the original turn.

Park a provably unsent queue entry outside the active queue unless confirmed Close covers it. Explicit owner Resume revalidates the original run, still-active originating session, repository revision, assets, provider and capacity before readmitting the same run ID. After original-session expiry or revocation, the same owner in a fresh session may explicitly settle a provably unsent parked run. Serialize settlement with all lease acquisition, persist terminal-unsent status and disable the old run permanently before offering restoration as a separately saved draft. Sending again requires a new explicit command and current destination confirmation. If the old effect cannot be excluded, keep it in recovery. Never boot-dispatch an uncertain operation.

On advance sleep notice, quiesce or revoke the writer before acknowledging sleep. Revalidate session, process generation, repository, channel and stop state after wake. Forced sleep can freeze a writer just before its syscall. An ordinary wake callback cannot prove it runs first. **Keep credentialed execution disabled until packaged qualification demonstrates that revalidation precedes any such work write.** Preserve an ambiguous prior handoff as unknown. An idle-sleep assertion or a successful synthetic mock cannot establish forced-sleep ordering.
